# PortfolioPilot 视觉设计规范

本文定义 PortfolioPilot 当前 Dashboard 与后续研究工作流界面的视觉目标、信息层级、状态语义、可访问性和组件约束。实际样式以 [`static/styles.css`](../static/styles.css) 中的设计变量为实现基线；文档用于评审一致性，不替代前端代码。

## 1. 视觉设计目标

PortfolioPilot 面向高频阅读数字、比较风险和复核证据的研究用户，界面应满足：

1. **信息优先**：组合、风险、证据和审核状态优先于装饰元素。
2. **可追溯**：关键结果附近应能看到 `as_of`、数据来源、模型/Prompt 版本或 evidence ID。
3. **状态明确**：真实、synthetic、mock、fallback、stale 和 unavailable 必须有可辨识文字，不只依赖颜色。
4. **密度可控**：桌面端支持扫描与比较，移动端保持阅读顺序，不通过缩小字体塞入全部列。
5. **主题一致**：支持浅色与深色主题，语义颜色在两种背景下保持足够对比度。

## 2. 信息层级

页面按以下优先级组织：

| 层级 | 内容 | 展示要求 |
|---|---|---|
| L1 | 组合净值、风险状态、数据截止时间、工作流状态 | 首屏可见，数字与状态标签并列 |
| L2 | 持仓、集中度、波动/回撤、证据和审核任务 | 支持表格比较、筛选和展开详情 |
| L3 | Price/FX lineage、Prompt version、Trace、规则结果 | 在详情面板或审计视图中可访问 |
| L4 | Experimental / Legacy 扩展 | 与核心研究路径分区，默认不抢占导航焦点 |

标题字号应与容器密度匹配。Dashboard 面板使用紧凑标题，不使用营销页式超大标题。重要数字使用 tabular numerals，并同时展示单位、币种和时间口径。

## 3. 颜色与状态

实现使用 CSS variables，避免在组件中重复硬编码颜色。核心变量包括：

```css
--bg-primary;
--bg-secondary;
--bg-card;
--text-primary;
--text-secondary;
--text-muted;
--border;
--accent-blue;
--accent-cyan;
--accent-purple;
--green;
--yellow;
--red;
```

### 3.1 语义颜色

| 状态 | 颜色角色 | 文案示例 |
|---|---|---|
| 正常、已批准、正收益 | `--green` | `已批准`、`+2.4%` |
| 待处理、降级、数据陈旧 | `--yellow` | `待审核`、`stale`、`degraded` |
| 失败、拒绝、高风险 | `--red` | `校验失败`、`已拒绝`、`high risk` |
| 信息、选中、可追溯链接 | `--accent-blue` / `--accent-cyan` | `查看 Trace`、当前 Tab |
| Experimental / AI 辅助标识 | `--accent-purple` | `LLM explanation` |

颜色不能是唯一状态载体。图标、标签或短文本必须同步表达含义。收益涨跌色与风险高低色应在上下文中明确，避免只显示一条没有刻度和标签的色带。

### 3.2 数据来源标签

建议使用以下固定文案：

- `provider`：真实 Provider 返回且保留来源；
- `research-only`：只适合研究演示的数据；
- `synthetic`：自行构造的数据；
- `mock`：确定性测试响应；
- `fallback`：主路径失败后的安全模板；
- `unavailable`：数据不足，指标不应显示为零。

## 4. 可访问性原则

1. 正文和交互控件应满足 WCAG AA 对比度目标。
2. 所有可点击图标必须提供 `aria-label` 或可见文本；不熟悉的图标应有 tooltip。
3. 键盘用户必须能按视觉顺序访问导航、表格操作、筛选、对话框和审核按钮。
4. `:focus-visible` 状态必须清晰，不能仅靠阴影变化。
5. 图表信息应同时提供文字摘要、数值或可访问表格。
6. 动画尊重 `prefers-reduced-motion`，加载状态不依赖闪烁。
7. 错误信息应指出字段和修复方式，并与输入通过 `aria-describedby` 关联。
8. 表格在窄屏可横向滚动或切换摘要视图，不压缩到无法阅读。

## 5. 组件规范

### 5.1 导航

- 核心导航顺序应围绕组合、风险、研究证据、工作流和评测。
- Experimental / Legacy 入口放入独立分组，不与核心路径同等级强调。
- 当前路由使用文字、图标和边框/背景共同表达，不只改变颜色。

### 5.2 卡片与面板

- 卡片用于单个指标组、重复项目或明确工具，不嵌套装饰性卡片。
- 面板标题包含主题；需要时在同一行展示 `as_of` 或状态。
- 圆角遵循现有 `--radius-sm/md/lg/xl`，同一层级保持一致。
- 空状态直接说明“无持仓”“无有效行情”或“无可用证据”，不得以 `0` 或空白伪装未知数据。

### 5.3 表格

- ticker、名称左对齐；数量、价格、权重、收益和风险指标右对齐。
- 币种、单位和小数精度在列标题或单元格中明确。
- 默认排序必须可见；筛选后显示结果数量。
- 行级操作使用图标按钮并提供 tooltip，破坏性操作需要确认。

### 5.4 表单与命令

- 二元配置使用 toggle/checkbox，模式选择使用 segmented control 或 tabs。
- 数字参数使用有范围和单位的 input/stepper，不用自由文本代替。
- 上传组件显示文件类型、大小限制、解析状态和 accepted/duplicate/rejected 真实计数。
- 提交后展示可追溯 ID，例如 portfolio ID、import batch、workflow run 或 trace ID。

### 5.5 审核状态

人工审核操作固定为：`批准`、`退回修改`、`拒绝`。每个操作显示当前版本、规则校验结果和引用状态；审核者身份来自服务端 Principal，界面不允许用户任意填写审计身份。

## 6. 数据展示规范

1. 所有金融数字明确币种、单位、符号和时间区间。
2. `null/unavailable` 显示为“暂无足够数据”并提供原因，不显示为 `0.0%`。
3. 风险分数必须同时显示量表范围和构成依据，例如 `6.2 / 10`。
4. 估值结果显示 `valuation_as_of`；行情与证据另显示各自 `data_as_of`。
5. 图表 tooltip 使用与表格一致的精度和时区。
6. Evidence 至少显示来源、发布日期、文档版本、chunk ID 和引用片段。
7. LLM 输出必须与 deterministic result 分区，避免用户误解模型生成内容是计算事实。
8. synthetic/mock/fallback 标签在结果区域持续可见，不能只在启动日志中出现。

## 7. 响应式与布局

- 固定格式的 KPI、图表和表格区域使用稳定尺寸或 `minmax()` 网格，加载状态不能引发布局跳动。
- 桌面端优先支持并排比较；窄屏按 L1 到 L4 顺序纵向排列。
- 侧栏折叠后保留熟悉图标与 tooltip。
- 文本不得与数字、按钮或图表重叠；长 ticker、文档标题和错误信息允许换行或截断并提供完整 tooltip。

## 8. 设计评审清单

- 是否在首屏说明当前组合、时间口径和数据状态？
- 是否把 deterministic 结果与 LLM 解释清楚分开？
- 是否能从结果追溯到行情、FX、evidence、Prompt 和 Trace？
- 空数据、陈旧数据和 Provider 失败是否有明确状态？
- 是否在浅色/深色、桌面/移动和键盘操作下可用？
- Experimental / Legacy 功能是否没有抢占核心投研路径？
- 页面是否避免宣传自动交易、收益承诺或未经验证的模型效果？
