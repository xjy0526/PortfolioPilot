# PortfolioPilot v2.0.0 Release Notes

> 发布状态：Release PR 准备中。本文是仓库内的正式版本说明，但尚未创建 `v2.0.0`
> Tag，也尚未发布 GitHub Release。最终发布必须以合并后的 `main` CI 为准。

## 1. 项目定位

PortfolioPilot 是一个面向基金投研场景的可追溯投资组合研究平台。系统将交易流水、市场数据、
风险分析和研究知识库统一到 PostgreSQL，通过受治理的 Hybrid RAG、Prompt Registry、LLM
Trace、确定性规则校验和人工审核工作流，生成带证据引用、可验证、可复核的研究结果。

本项目是工程与研究演示，不执行真实交易，不构成投资建议、交易指令、收益承诺或机构合规认证。

## 2. 核心架构

主链路由以下组件组成：

```text
CSV/API -> PostgreSQL Transaction Ledger -> Position Rebuilder
        -> Point-in-time Price/FX Valuation -> Risk Analytics
        -> PostgreSQL FTS + pgvector + RRF -> Structured LLM Draft
        -> Numeric/Citation/Compliance Validation -> Human Review
        -> Published Research Report
```

FastAPI 请求和 Worker 任务各自使用独立 SQLAlchemy AsyncSession。Alembic 独占数据库 schema
变更；应用 import 和启动不调用 `Base.metadata.create_all()`。对象原文由统一 storage abstraction
管理，数据库保存 object key、checksum、版本和权限元数据。

## 3. PostgreSQL Ledger

- PostgreSQL `transactions` 是持仓事实源，position snapshot 是派生结果。
- 支持标准交易流水 CSV、行级校验、文件 SHA256、幂等导入和错误报告。
- 数量、金额、价格和汇率使用 `NUMERIC`，时间以 UTC 持久化。
- `buy`、`sell`、现金流、分红、费用、税和拆股由确定性账本语义处理。
- 旧持仓 CSV 仅转换成明确标记的 `opening_balance`，不会伪装成完整交易历史。
- `legacy_dashboard_csv` 使用 active/superseded generation 表达“当前持仓快照”替换语义，
  不会覆盖 standard CSV、manual 或其他正式交易来源。

## 4. Point-in-time Valuation

- Position Rebuilder 按 `occurred_at`、`created_at` 稳定排序重放交易。
- 估值只读取不晚于指定 `as_of`/data cutoff 的 PriceBar 和历史 FX。
- 原始行情保留 native currency，组合估值时转换到 base currency。
- position snapshot 保存 price/FX lineage、原币价格、换算汇率、成本和未实现盈亏。
- valuation snapshot 保存 input hash、数据质量、覆盖率、代码版本和运行来源。
- 回测使用明确成交约定、漂移权重、交易成本和缺失行情语义，避免提前收益。

## 5. Governed RAG

- 研究文档、版本、Chunk、Embedding、有效期和权限持久化到 PostgreSQL/pgvector。
- 上传对象进入 S3-compatible 或 development local storage，再由独立 Worker 解析和 Embedding。
- 检索在排序前执行服务端 ACL 与时点过滤。
- PostgreSQL 全文检索和 pgvector 向量结果通过 RRF 融合，可选 reranker。
- 引用保留 document/version/chunk ID、quote、score 和权限/有效性状态。
- 没有足够证据时返回 evidence insufficient，而不是补写无来源事实。

## 6. Prompt Registry 与 LLM Trace

- Prompt 使用不可变版本、draft/publish/rollback 和 deployment 记录。
- Qwen/OpenAI-compatible client 只处理受约束的结构化生成。
- Trace 记录 provider、model、Prompt version、证据 ID、usage、成本来源、fallback、代码版本和时间。
- 模型输出必须通过 JSON schema、ticker、数字和 citation consistency 校验。
- 确定性优化器负责目标权重；LLM 只能解释风险、证据和复核优先级。

## 7. Human Review

- Research Workflow 使用固定节点、工具 allowlist、节点超时、租约恢复和幂等 checkpoint。
- reviewer identity 来自服务端 Principal，不接受请求 Body 自报身份。
- approve、reject 和 request changes 都保留审计记录。
- 只有规则校验和人工批准完成的报告才能发布。

人工审核工作流已经实现，但评测集 `evaluation/datasets/v2` 当前实际为：

- `approved_case_count=0`
- `pending_case_count=60`

因此 v2.0.0 没有可对外宣传的 human-gold 模型质量指标。

## 8. Deterministic Demo

当前发布树提供无需模型凭据的 deterministic synthetic smoke：

```bash
python -m evaluation.run_v2_eval \
  --mode synthetic_smoke \
  --output cache/evaluation/v2/synthetic_smoke/release.json
```

其数据 schema 版本为 `2.0.0`，来源与边界记录在
[`data/demo_fixture_manifest.json`](../../data/demo_fixture_manifest.json)。报告必须显示 synthetic/mock
与 provenance 字段；这些结果只验证工程链路和规则，不代表真实模型效果。

完整的 `make demo` PostgreSQL seed、Trace、Review、Published Report 一键链路仍位于未合并工作中，
不属于本次 v2.0.0 候选树。本文不会把它表述成已发布能力。

## 10. 测试与 CI

GitHub Actions 将验证六个独立 Job：

1. Ruff、Mypy、synthetic smoke 与非 PostgreSQL tests；
2. PostgreSQL integration 与 Alembic round trip；
3. 真实 PostgreSQL restart persistence E2E；
4. total/core/changed-lines coverage gate；
5. pip-audit 与 Gitleaks；
6. production Docker build。

Release PR 的测试数量和覆盖率以该 SHA 对应的 Actions run 与 artifact 为准，不在长期文档中写入
会随后续提交失效的“当前数字”。Synthetic smoke 不是 live model 或生产准确率测试。

## 11. 安全边界

- 不提交 API Key、Token、密码、真实个人持仓、内部研报或授权受限数据。
- production identity 由服务端建立；development identity header 在 production 被拒绝。
- production write mode 必须使用 S3-compatible storage，不能静默回退 local。
- 上传受 content type、大小、页数、Chunk 数和解析超时限制。
- read-only deployment 的 mutation 统一返回 403。
- Provider credentials 通过环境或 Secret Manager 注入，不写入 Docker image、Blueprint 或日志。

## 12. 迁移说明

完整步骤见 [`v2.0.0-migration.md`](v2.0.0-migration.md)。核心顺序是：

1. 备份数据库、对象存储和配置；
2. 部署 PostgreSQL 16 + pgvector；
3. 执行 `alembic upgrade head`；
4. 检查 legacy snapshot generation 与 valuation lineage；
5. 配置 S3、认证、Embedding 和 Provider；
6. 运行 `python -m app.core.preflight`；
7. 先以 read-only 模式验证，再开放写流量。

不要修改已发布 migration revision，也不要在没有可恢复备份时对生产库执行 downgrade。

## 13. 已知限制

- 回测具备 point-in-time 约束，但不是完整生产级 walk-forward 平台。
- yfinance 仅用于研究演示，没有生产 SLA；A 股正式使用需要合法授权的行情源。
- 当前 release tree 不含一键 governed demo、showcase UI、V3 双人 human-gold 流程或 stale legacy
  valuation 自动修复脚本。
- `0007` generation migration 不会自动重建旧 valuation；升级后必须按迁移文档扫描并重建。
- 当前 approved human labels 为 0；没有 live model 或 production monitoring 质量结论。
- Basic Auth、hashing embedding 和 local object storage 只适合 development/test/demo。
- SQLite 与部分旧 routes/services/fetchers 仍作为 compatibility/experimental 路径存在。
- 仓库没有完成真实 S3 bucket、正式 SSO、备份恢复和灾备演练。

## 14. 本版本不包含

- 真实券商下单、自动交易或自动执行调仓；
- 投资建议、收益承诺或机构合规认证；
- 生产级智能投顾或真实基金公司部署声明；
- 未披露的 mock/fallback、伪造模型指标或伪造人工标签；
- Telegram、Shadow Agent、Trade Advisor、Tech Radar、Polymarket 或 Parqet 作为核心依赖；
- `v2.0.0` Tag 或 GitHub Release（仅在 Release PR 合并并通过 main CI 后创建）。
