# PortfolioPilot v2.0.0 发布草案

> **Draft only.** 本文描述当前 `main` 主线的发布候选叙事。仓库尚未创建正式 `v2.0.0` Release 或 Tag；只有后续独立发布验收通过后，才能将本文件转为正式 Release Notes。

## 当前主线定位

PortfolioPilot 是一个面向基金投研场景的可追溯 AI 工作流平台。系统以 PostgreSQL 交易账本和时点估值生成确定性组合风险结果，通过受治理的 Hybrid RAG 检索可引用证据，并结合 Prompt/LLM Trace、规则校验与人工审核生成可复核研究报告。

项目用于金融研究与软件工程演示，不连接券商、不执行真实交易，也不构成投资建议、机构合规认证或收益承诺。

## 已完成能力

### Portfolio Ledger & Valuation

- PostgreSQL `transactions` 是组合持仓和现金的事实源。
- 支持标准交易 CSV 幂等导入，以及明确标记为 `opening_balance_only` 的旧持仓快照兼容。
- Position Rebuilder 按 `as_of` 重放交易，支持加权平均成本、多币种现金和负持仓校验。
- 估值快照关联历史 PriceBar、FX、统一数据截止时间、输入哈希和 source lineage。

### Risk Analytics & Backtest

- 确定性计算收益、波动、最大回撤、Sharpe、资产权重、行业集中度和资产类型暴露。
- 回测区分 buy-and-hold 与 periodic rebalanced original，保存权重漂移、执行口径、成本和 eligible universe。
- 缺失行情不被无条件解释为零收益；Benchmark 无有效覆盖时相关指标返回 `null`。

### Governed Hybrid RAG

- 文档、版本、Chunk、Embedding、权限和有效期持久化到 PostgreSQL/pgvector。
- 入库时生成 embedding；查询时只编码 query。
- 权限、发布版本和时效过滤先于排名，检索融合 PostgreSQL FTS、pgvector 和 RRF。
- Evidence 保留 document/version/chunk 引用 lineage。

### Prompt、Trace 与人工审核

- Prompt Registry 支持不可变版本、发布和回滚。
- LLM Trace 记录模型、Prompt、证据、usage 来源、成本来源、代码版本和数据截止时间。
- 确定性规则负责数字和引用校验；LLM 不直接修改目标权重。
- Workflow 支持节点 checkpoint、租约恢复、人工批准/退回/拒绝和幂等发布。

### 工程与部署

- Python 3.12、FastAPI、SQLAlchemy Async、asyncpg、Alembic、PostgreSQL 16 和 pgvector。
- Web、Cron 和 Worker 使用独立 Session；production 可写模式要求共享 S3-compatible object storage。
- CI 分层运行 lint/type/unit、PostgreSQL integration、restart persistence E2E、security audit、coverage gate 和 Docker build。

## 测试与评测边界

- 当前真实 CI 状态以 [`main` push workflow](https://github.com/xjy0526/PortfolioPilot/actions/workflows/ci.yml?query=branch%3Amain+event%3Apush) 为准；本文不写死会随提交失效的测试数量或覆盖率。
- PostgreSQL restart E2E 会真实重启 Compose 数据库，并验证账本、估值、文档、embedding、Prompt、Trace、Workflow、审核和报告元数据持久存在。
- `synthetic_smoke` 使用自行构造 fixture 和 deterministic mock，只验证工程链路与规则。
- `live_model_eval` 禁止静默回退 mock；没有模型凭据或合规 prediction bundle 时不生成 live 指标。
- `human_gold_eval` 只允许使用 independently approved labels；当前不能把自动生成标签宣传为人工黄金集。
- `production_monitoring` 必须读取真实生产观测，没有数据时拒绝生成报告。

这些检查不能替代渗透测试、生产 SLA、金融合规评估或真实模型效果验证。

## 数据披露

- 仓库示例持仓、交易和组合均为 synthetic 数据。
- 研究文档来自公开来源元数据或项目自行编写的培训摘要，不包含内部研报或付费内容副本。
- yfinance 仅用于研究演示；生产数据需要授权 Provider、数据质量协议和供应商故障切换。
- Mock、fallback、estimated usage 和 research-only 数据必须在结果中显式标记。

## 与旧个人 Dashboard 的变化

| 旧叙事 | v2 主线 |
|---|---|
| 个人 AI 投资组合 Dashboard | 面向基金投研流程的可追溯研究平台 |
| 本地 CSV/全局 state 可作为组合来源 | PostgreSQL transaction ledger 是唯一事实源 |
| 以单个模型或聊天入口为中心 | Provider-neutral structured output、Prompt Registry 和 Trace |
| 本地文档或临时向量索引 | PostgreSQL/pgvector 持久化、ACL、版本和时效治理 |
| 模型直接给出调仓动作 | 确定性优化器计算权重，LLM 只解释风险与证据 |
| 发布结果缺少正式审核边界 | 规则校验、人工审核和幂等发布 |

Telegram、Shadow Agent、Tech Radar、Trade Advisor、Parqet compatibility、Polymarket 和旧 SQLite Dashboard 数据流仍保留为默认关闭的 Experimental / Legacy 扩展，不属于 v2 核心定位。

## 已知限制

- 回测已有 point-in-time 执行边界，但尚无完整生产交易日历、退市和公司行动数据库。
- 当前认证仍是演示级 Basic Auth/服务端 Principal，未接入机构 OIDC/SAML 生命周期。
- production write mode 需要外部 PostgreSQL、S3-compatible storage、正式密钥管理和备份恢复；仓库不提供托管基础设施。
- Tushare/yfinance Provider 尚未具备生产级并发限流、断点续传和授权 SLA。
- 当前没有与最新主线完全一致的公开在线 Demo、截图或 GIF。
- V2 数据集当前不支持对外宣称 human-gold、真实模型准确率或生产监控效果。

更完整的边界和 mock/fallback 条件见 [当前限制](../current-limitations.md)。
